# 입주ON · 잔금대출 상담 관리 시스템

은행 잔금대출 상담사가 엑셀 없이 사이트 안에서 상담부터 대출실행 정산까지 완결 처리할 수 있도록 만드는 웹 애플리케이션입니다. 본 문서는 Claude Code가 일관된 맥락으로 개발하도록 프로젝트 루트에 둡니다.

> **v3 (스크롤 최소화 전면 적용)**: 모든 주요 화면이 1920×1080 한 화면에 들어오도록 밀도·레이아웃 규칙 정의. v2의 6단계 플로우 유지.

---

## 1. 프로젝트 개요

### 1.1 서비스 정의
- **이름**: 입주ON
- **사용자**: 은행 잔금대출 상담사
- **업무 범위**: 아파트 입주 시점 집단 잔금대출 처리 전 과정
- **핵심 가치**: 엑셀/별도 파일 없이 사이트 하나로 모든 업무 완결

### 1.2 대체하는 도구
- 고객 관리 엑셀 (총괄 파일)
- 정산 엑셀 (상환조회, 은행별 계좌 관리)
- 은행 담당자 연락처 목록
- 자서 일정 캘린더
- 메모장, SMS 전송용 개별 도구

### 1.3 핵심 설계 원칙
1. **엑셀 완전 대체** — 정산의 모든 항목을 사이트 안에서 처리
2. **모든 화면 스크롤 제로** — 1920×1080 한 화면 완결 (본 문서 2장 참조)
3. **입주기간 집중 지원** — 평상시 vs 입주기간 2~3주 모드 구분
4. **긴급도 자동 판정** — 단순 체류일 + 입주일 D-day 교차 판단
5. **실시간 소통 지원** — 비고/메모가 구조화된 체크로 전환
6. **자동 계산** — 정산 합계·필요자금·환급액 자동

## 2. 스크롤 최소화 설계 원칙 (전체 화면 공통)

### 2.1 7대 원칙

1. **기준 해상도** — 1920×1080 (Full HD 데스크탑). 헤더·푸터 제외하면 **실제 사용 영역 약 970px 높이**. 이 안에 모든 주요 정보 배치.
2. **"더 보기"는 있어도 "스크롤"은 없음** — 정보가 많으면 숨기지 말고 밀도를 높임. 폰트 11~12px, 여백 최소화.
3. **세로보다 가로** — 세로로 쌓지 말고 가로로 펼침. 3단·4단 분할 적극 활용.
4. **테이블보다 그리드, 리스트보다 칸반** — 세로 행이 무한정 늘어나는 구조 피함.
5. **모달 안에도 스크롤 없음** — 탭 대신 좌우 분할, 탭이 필요하면 상단 고정.
6. **페이지네이션 + 필터로 리스트 제어** — 한 페이지 최대 15~20행. 필터 칩으로 좁혀서 보게 유도.
7. **서브 해상도 대응** — 1366×768(노트북)까지만 대응. 모바일은 지원하되 기본 타겟 아님.

### 2.2 세로 공간 예산 (1920×1080 기준)

```
총 1080px
├─ 브라우저 UI      약 100px (탭, 주소창)
├─ 애플리케이션 헤더  50px
├─ 필터/서브 네비    40px
├─ 본문 영역        약 840px  ← 여기에 모든 콘텐츠
├─ 푸터/상태바       40px
└─ OS 작업표시줄     10px
```

### 2.3 밀도 규칙

| 요소 | 표준 | 고밀도 (리스트·대시보드) |
|---|---|---|
| 본문 폰트 | 14px | 11~12px |
| 라벨 폰트 | 13px | 10~11px |
| 섹션 헤더 | 14px / 500 | 10px / 500 / uppercase |
| 행 높이 (리스트) | 40px | 28px |
| 입력 필드 높이 | 36px | 24~28px |
| 필드 세로 간격 | 16px | 3~4px |
| 섹션 간 간격 | 24px | 10~12px |
| 버튼 높이 | 36px | 24~28px |
| 버튼 패딩 | 0 16px | 0 10~12px |

### 2.4 레이아웃 분할 패턴

**3단 분할** — 상담 모달, 대출실행 정산 화면
```
[240px 고정]  [유동]  [240px 고정]
고정 정보      핵심     보조 UI
```

**좌측 사이드 + 우측 본문** — 파이프라인, 메인 목록
```
[170px 사이드]  [나머지 본문]
단계별 카운트    리스트/대시보드
```

**4단 KPI + 3단 패널** — 대시보드
```
[1fr] [1fr] [1fr] [1fr]  ← KPI 카드 4개
[1.3fr]  [1fr]  [1fr]    ← 상세 패널 3개
```

### 2.5 "스크롤 금지" 체크리스트

새 화면을 만들기 전에 아래를 확인:
- [ ] 1920×1080에서 세로 스크롤 없이 모든 정보 보이는가?
- [ ] 1366×768에서도 핵심 정보가 보이는가? (부가 정보만 축소/숨김 허용)
- [ ] 모달 내부에 스크롤이 없는가?
- [ ] 리스트가 길어질 경우 페이지네이션/필터가 있는가?
- [ ] 탭이 필요한가? 탭을 없애고 좌우 분할로 해결 가능한가?

## 3. 업무 플로우 (6단계)

### 3.1 파이프라인

```
1. 상담 → 2. 가심사 → 3. 가심사결과 안내 → 4. 자서예약 → 5. 자서 → 6. 대출실행
```

모든 단계에서 `취소` 분기 가능. 취소 사유 필수 기록.

### 3.2 단계별 상세

| 단계 | 핵심 활동 | 주요 산출물 | 다음 단계 조건 |
|---|---|---|---|
| 상담 | 고객 정보·물건, 소득·기존대출, 한도 시뮬레이션 | 상담 시트, 예상 한도 | 고객 진행 의사 확인 |
| 가심사 | 서류 취합, 은행 심사 요청 | 서류 완비, 은행 접수일 | 은행 심사 결과 도착 |
| 가심사결과 안내 | 승인금액·금리 통보, 수용 확인 | 승인 조건, 수용 기록 | 고객 진행 수락 |
| 자서예약 | 자서일 확정, 지참서류 안내 | 자서 일정, 준비물 안내 | 자서일 도래 |
| 자서 | 계약서 서명, 정산 금액 입력 준비 | 서명 완료, 실행일 확정 | 실행일 도래 |
| 대출실행 | 기표, 각 계좌 정산 송금, 필요자금 수납 | 정산 완료, 실행 완료 | 전 항목 정산 완료 |

### 3.3 업무 리듬

| 시기 | 특성 | 주로 쌓이는 단계 |
|---|---|---|
| 평상시 (입주 D-60 ~ D-15) | 신규 상담, 가심사 진행 | 1~3단계 |
| 입주 집중기간 (D-14 ~ D+7) | 자서·실행 폭증 (일 5~10건) | 4~6단계 |
| 입주 후 (D+8 ~) | 잔여 건 마무리, 사후관리 | 6단계 + 사후 |

## 4. 긴급도 판정 체계

### 4.1 단계별 SLA

| 단계 | 정상 | 주의 | 긴급 | 위험 |
|---|---|---|---|---|
| 상담 | ~3일 | 4~7일 | 8일+ | 14일+ |
| 가심사 | ~2일 | 3~4일 | 5일+ | 7일+ |
| 가심사결과 안내 | 당일~1일 | 2일 | 3일+ | 5일+ |
| 자서예약 | ~3일 | 4~6일 | 7일+ | 10일+ |
| 자서→실행 | 당일~2일 | 3일 | 4일+ | 6일+ |
| 실행 | 당일 | — | 1일+ | 2일+ |

### 4.2 입주일 D-day 교차 판정

| 조건 | 최종 긴급도 |
|---|---|
| 자서 완료 + 실행 미완 + 입주일 경과 | 위험 |
| 자서 완료 + 실행 미완 + 입주일 당일 | 최우선 |
| 자서 미완 + 입주일 D-3 이내 | 최우선 |
| 자서 완료 + 실행 미완 + 입주일 D-3 이내 | 긴급 |
| 실행 완료 + 입주일 전 | 정상 |

### 4.3 추가 긴급 규칙
1. 이사일 D-3 이내인데 실행 안 됨 → 최우선
2. 잔금납부 기한 D-1 이내 → 긴급
3. 은행 서류 보완 요청 3일 미답변 → 긴급
4. 자서일에 필요 서류 미준비 → 긴급
5. 동일 계약자 전화 부재 3회 이상 → 주의
6. 동일 시간대 자서 일정 충돌 → 주의

### 4.4 규칙 엔진

```typescript
type UrgencyLevel = 'normal' | 'warning' | 'urgent' | 'critical';

interface UrgencyRule {
  id: string;
  when: (data: ConsultationData, today: Date) => boolean;
  level: UrgencyLevel;
  message: string;
}
```

### 6.2 단계별 리스트 컬럼 (동적 구성)

| 단계 | 컬럼 구성 |

| 3. 결과안내 | 고객명, 동/호, 승인금액, 금리, 통보여부, 액션 |
| 4. 자서예약 | 고객명, 동/호, 자서일/시간, 지참서류, 액션 |
| 5. 자서 | 고객명, 동/호, 연락처, 담당, 대출은행, 실행예정, 입주D-day, 체류/긴급도, 액션 |

### 7.2 시간대 압축

잔금대출 업무 특성상 9~16시에 자서·실행이 집중됨. 새벽·심야는 표시 안 함.

표시: **9시, 10시, 11시, 14시, 15시, 16시** (점심 12~13시 제외)

### 7.3 이벤트 색상

| 종류 | 색상 | 용도 |
|---|---|---|
| 자서 | 파랑 | 자서 예약 |
| 실행 | 초록 | 대출 실행 |
| 이사일 | 노랑 | 고객 입주일 |
| 긴급/지연 | 빨강 | 긴급 처리 필요 |

### 7.4 충돌 감지

- 같은 시간대 자서 2건 이상 → ⚠ 충돌 배지
- 셀 우상단에 ● 개수 표시
- 드래그로 다른 시간대 이동 가능

### 7.5 필터

- 이벤트 종류: 자서 / 실행 / 이사일 / 전체
- 담당자: 내 담당 / 전체 상담사
- 뷰: 주간 (기본) / 월간

## 8. 긴급 대시보드 (입주기간 전용)

### 8.1 레이아웃

```
헤더(50) + KPI(110) + 패널(400) + 여백 = 약 560px
```

```
┌──────────────────────────────────────────────────────────────┐
│ 헤더: 대시보드 · D-day 배지 · 자동갱신 표시 (50px)          │
├──────┬──────┬──────┬──────┐                                  │
│ KPI1 │ KPI2 │ KPI3 │ KPI4 │  4개 나란히 (110px)             │
├──────┴──────┴──────┴──────┤                                  │
├──────────┬────────┬───────┤                                  │
│ 최우선   │ 오늘   │ 부하  │                                  │
│ 처리     │ 일정   │ &추이 │  3단 패널 (400px)               │

│          │        │       │                                  │

```

### 8.2 KPI 카드 4개 (상단)

1. **최우선 처리** (빨강) — 자서 후 4일+ / 입주일 초과 건수
2. **오늘 실행 예정** (노랑) — 자서 완료 · 정산 대기
3. **오늘 자서** (회색) — 내 담당 건수 포함 표시
4. **이번 주 완료** (초록) — N/목표 + 달성률 + 평균 체류일

### 8.3 3단 패널

**좌측 (1.3fr) — 최우선 처리 리스트**
- 자서 후 4일+ / 입주일 D-3 이내 / 실행 지연 건
- 각 행: D-day · 고객명 · 동/호 · 경과일 태그
- 클릭 시 해당 고객 상세 모달

**중앙 (1fr) — 오늘 일정**
- 오늘 자서 일정 (시간 + 고객명 + 은행)
- 오늘 실행 일정 (시간 + 고객명 + 준비 상태)
- 시간 충돌 시 빨간 표시

**우측 (1fr) — 담당자별 부하 + 주간 추이**
- 담당자별 오늘 건수 바 차트
- 과부하 자동 감지 (9건+ = 빨강, 6건+ = 노랑)
- 이관 제안 자동 생성
- 주간 달성 추이 미니 막대 그래프

### 8.4 자동 갱신

- 1분마다 자동 새로고침
- 긴급 건 추가 시 토스트 알림
- 마지막 업데이트 시각 상단 표시

```
└──────────────────────────────────────────────────────────────┘
```

### 10.2 정산 테이블 (중앙)

각 정산 항목에 대해 컬럼: 항목 · 은행 · 상환 계좌 · 금액 · 입력 상태

| 항목 | 원금 | 이자 | 비고 |
|---|---|---|---|
| 중도금 | O | O | 중도금 대출 은행 계좌 |
| 분양잔금 | O | O | 시행사 계좌 |
| 발코니 확장 | O | — | 시행사 계좌 |
| 유상옵션 | O | — | 시행사 계좌 |
| 보증수수료 (대납이자) | — | O | 시행사 계좌 |
| 선수관리비 | O | — | 관리사무소 계좌 |
| 이주비 | O | — | 이주비 은행 계좌 |
| 인지대 (대출) | O | — | 정액 |
| 인지대 (추가대출) | O | — | 정액 |

소계: 중도금 합계 · 분양잔금 합계
총합: 상환 금액 합계(A) · 대출금(B)
**필요자금 = A - B** (양수 빨강, 음수 초록, 0 회색)

### 10.3 우측 컬럼

- **필요자금 판정** (대형 KPI 카드) — 추가 납부 or 환급 금액
- **입금 확인 체크리스트** — 대출 연계 / 고객 추가 입금 / 센터 통보 / 기표 완료
- **실시간 메모** — 타임스탬프 자동 기록, 로그 누적식
- **긴급 연락처** — 건별 담당자 + 공용 연락처 (대출은행, 중도금은행, 입주지원센터, 법무사)

### 10.4 자동 계산 규칙

```
상환 총액 (A) = 중도금 합계 + 분양잔금 합계 + 발코니 + 유상옵션
              + 보증수수료 + 선수관리비 + 이주비 + 인지대(대출) + 인지대(추가대출)
대출 총액 (B) = 대출금액 + 추가대출
필요자금 = A - B
```

모든 숫자는 반올림 (부동소수점 오차 방지), 천단위 콤마 표시.
